# Timity Firestore collections and rules

Everything you need to create in the Firebase console, in one place. Copy the rules at the
bottom into **Firestore Database → Rules** and publish.

Firestore creates collections on the first write, so you do not have to add them by hand. The
list below is the contract the app and the rules both follow. If you want to see them in the
console right away, add one document to each with the sample values.

## Layout

```
users/{uid}                        one document per signed-in user (can stay empty)
  settings/prefs                   one document, fixed id "prefs"
  entries/{entryId}                one document per clock in / clock out session
  holidays/{holidayId}             synced (Calendarific) and custom days off
  periods/{periodId}               Ramadan-style working-hour periods
```

- `uid` is the Firebase Authentication user id (Anonymous or Google sign-in).
- `entryId`, `holidayId`, `periodId` are auto ids generated by Firestore.
- Every document carries `updatedAt` in epoch milliseconds. The app keeps the newest copy when
  the phone and the cloud disagree.
- All times are stored as numbers, never as Firestore Timestamps, so the values match the Room
  database on the phone one to one.

## 1. `users/{uid}/settings/prefs`

One document. The Calendarific API key is **not** stored here; it stays on the phone.

| field | type | allowed values / notes |
|---|---|---|
| overtimeRate | number | MVR per hour, 0 or more |
| standardHours | number | hours per day, 0 to 24 |
| overtimeMode | string | `OUTSIDE_WORKING_HOURS` or `BEYOND_STANDARD_HOURS` |
| workStart | integer | minutes from midnight, 0 to 1439 (09:00 is 540) |
| workEnd | integer | minutes from midnight, 0 to 1439 (16:00 is 960) |
| weekendDays | array of string | any of `MONDAY` … `SUNDAY`, default `["FRIDAY","SATURDAY"]` |
| theme | string | `SYSTEM`, `LIGHT`, `DARK` |
| holidaysSyncedAt | integer | epoch millis of the last Calendarific sync, 0 if never |
| updatedAt | integer | epoch millis |

Sample document:

```json
{
  "overtimeRate": 75.0,
  "standardHours": 8.0,
  "overtimeMode": "OUTSIDE_WORKING_HOURS",
  "workStart": 540,
  "workEnd": 960,
  "weekendDays": ["FRIDAY", "SATURDAY"],
  "theme": "SYSTEM",
  "holidaysSyncedAt": 1762099200000,
  "updatedAt": 1762099200000
}
```

## 2. `users/{uid}/entries/{entryId}`

One document per work session.

| field | type | allowed values / notes |
|---|---|---|
| clockIn | integer | epoch millis |
| clockOut | integer or null | null while still clocked in, otherwise ≥ clockIn |
| note | string | comment typed at clock out, may be empty, max 500 characters |
| updatedAt | integer | epoch millis |

Sample document:

```json
{
  "clockIn": 1762152000000,
  "clockOut": 1762182000000,
  "note": "Month-end closing",
  "updatedAt": 1762182000000
}
```

Queries the app runs: `where clockIn >= from and clockIn < to, orderBy clockIn`. Firestore
builds the single-field index on `clockIn` automatically, so no composite index is needed.

## 3. `users/{uid}/holidays/{holidayId}`

Days off. Synced days come from Calendarific; custom days are added in Settings with the
Holiday, Sick day and Day off buttons.

| field | type | allowed values / notes |
|---|---|---|
| epochDay | integer | days since 1970-01-01 (2026-11-03 is 20760) |
| name | string | 1 to 120 characters |
| type | string | Calendarific type such as `National holiday`, or `Custom`, `Sick day`, `Day off` |
| source | string | `calendarific` or `custom` |
| enabled | boolean | true means any work on that day counts as overtime |
| updatedAt | integer | epoch millis |

The pair `epochDay` + `name` must be unique per user. The app enforces it; Firestore has no
unique constraint, so the sync uses the deterministic id `"{epochDay}_{name}"` for synced days
to avoid duplicates on re-sync.

Sample document:

```json
{
  "epochDay": 20760,
  "name": "Victory Day",
  "type": "National holiday",
  "source": "calendarific",
  "enabled": true,
  "updatedAt": 1762099200000
}
```

## 4. `users/{uid}/periods/{periodId}`

Named date ranges with their own working hours, such as Ramadan. When today falls inside an
enabled period, its hours replace the defaults; outside it the app returns to the defaults.

| field | type | allowed values / notes |
|---|---|---|
| name | string | 1 to 60 characters, e.g. `Ramadan 2026` |
| startEpochDay | integer | first day, inclusive |
| endEpochDay | integer | last day, inclusive, ≥ startEpochDay |
| workStart | integer | minutes from midnight, 0 to 1439 |
| workEnd | integer | minutes from midnight, 0 to 1439 |
| standardHours | number | 0 to 24 |
| enabled | boolean | |
| updatedAt | integer | epoch millis |

Sample document:

```json
{
  "name": "Ramadan 2026",
  "startEpochDay": 20500,
  "endEpochDay": 20529,
  "workStart": 540,
  "workEnd": 780,
  "standardHours": 4.0,
  "enabled": true,
  "updatedAt": 1762099200000
}
```

## 5. Authentication

Enable in **Authentication → Sign-in method**:

- **Anonymous**: required. The app signs in silently on first launch so every phone gets a uid.
- **Google**: optional. Lets you link the anonymous account to your Google account and restore
  the data on a new phone.

## 6. Security rules

Paste this into **Firestore Database → Rules** and press Publish. It is the same text as
`firestore.rules` in the repo root.

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // A user can only read and write documents under their own uid.
    match /users/{uid} {
      allow read, write: if isOwner(uid);

      match /settings/{docId} {
        allow read, delete: if isOwner(uid);
        allow create, update: if isOwner(uid) && validSettings(request.resource.data);
      }
      match /entries/{entryId} {
        allow read, delete: if isOwner(uid);
        allow create, update: if isOwner(uid) && validEntry(request.resource.data);
      }
      match /holidays/{holidayId} {
        allow read, delete: if isOwner(uid);
        allow create, update: if isOwner(uid) && validHoliday(request.resource.data);
      }
      match /periods/{periodId} {
        allow read, delete: if isOwner(uid);
        allow create, update: if isOwner(uid) && validPeriod(request.resource.data);
      }
    }

    // Everything else is closed.
    match /{document=**} {
      allow read, write: if false;
    }

    function isOwner(uid) {
      return request.auth != null && request.auth.uid == uid;
    }

    function minutesOfDay(v) {
      return v is int && v >= 0 && v < 1440;
    }

    function validSettings(d) {
      return d.overtimeRate is number && d.overtimeRate >= 0
        && d.standardHours is number && d.standardHours >= 0 && d.standardHours <= 24
        && d.overtimeMode in ['OUTSIDE_WORKING_HOURS', 'BEYOND_STANDARD_HOURS']
        && minutesOfDay(d.workStart) && minutesOfDay(d.workEnd)
        && d.weekendDays is list && d.weekendDays.size() <= 7
        && d.theme in ['SYSTEM', 'LIGHT', 'DARK']
        && d.holidaysSyncedAt is int && d.holidaysSyncedAt >= 0
        && d.updatedAt is int;
    }

    function validEntry(d) {
      return d.clockIn is int && d.clockIn > 0
        && (!('clockOut' in d) || d.clockOut == null
            || (d.clockOut is int && d.clockOut >= d.clockIn))
        && d.note is string && d.note.size() <= 500
        && d.updatedAt is int;
    }

    function validHoliday(d) {
      return d.epochDay is int
        && d.name is string && d.name.size() > 0 && d.name.size() <= 120
        && d.type is string && d.type.size() > 0 && d.type.size() <= 60
        && d.source in ['calendarific', 'custom']
        && d.enabled is bool
        && d.updatedAt is int;
    }

    function validPeriod(d) {
      return d.name is string && d.name.size() > 0 && d.name.size() <= 60
        && d.startEpochDay is int && d.endEpochDay is int
        && d.endEpochDay >= d.startEpochDay
        && minutesOfDay(d.workStart) && minutesOfDay(d.workEnd)
        && d.standardHours is number && d.standardHours >= 0 && d.standardHours <= 24
        && d.enabled is bool
        && d.updatedAt is int;
    }
  }
}
```

What the rules guarantee:

- Nobody can read or write without being signed in.
- A signed-in user can only touch `users/<their own uid>/...`. Even a second Timity user with a
  valid account gets a permission error on your documents.
- Every create and update is type-checked. A document with a missing field, a wrong type, a
  clock out before the clock in, or a working hour outside 0 to 1439 is rejected.
- Deletes only need ownership, so the app can remove a row without re-sending the whole
  document.

## 7. Indexes

None to create. All queries use a single field (`clockIn`, `epochDay`, `startEpochDay`), and
Firestore indexes single fields automatically.
